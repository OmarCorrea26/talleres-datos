# Introducción

### ¿A quién va dirigido este taller?

Este material está pensado para analistas estadísticos que vienen de SAS, R o Excel avanzado y que necesitan dar el salto a Python. La razón puede ser una de varias: automatizar procesos que hoy son manuales, colaborar en proyectos compartidos en GitHub, o integrarse con flujos modernos de datos que ya están en Python.

No se requiere experiencia previa en Python ni en programación de uso general. Pero sí se aprovecha tu base estadística: en cada concepto nuevo hay un paralelo con SAS y R para que ancle más rápido.

### ¿Qué vas a aprender?

El taller tiene cinco módulos secuenciales. Cada uno construye sobre el anterior pero pueden retomarse de forma independiente — si te pierdes en el 3 no pasa nada por revisar el 2 de nuevo.

| Módulo | Tema | Resultado al finalizar |
|----|----|----|
| 0 | Antes de empezar | Python y VSCode instalados y verificados |
| 1 | Tu primer proyecto en Python | Un script .py corriendo desde la terminal |
| 2 | De Jupyter a .py | Un notebook migrado a script reutilizable |
| 3 | Git y GitHub | Tu código versionado y publicado en un repo |
| 4 | Asistentes de IA en el IDE | Una función nueva implementada con apoyo de IA |

Esta guía cubre los cinco módulos completos del taller. Cada uno construye sobre el anterior, pero todos pueden retomarse de forma independiente.

### ¿Cómo está organizada cada sección?

Todos los módulos siguen el mismo esqueleto: un objetivo claro al inicio, un checklist de prerequisitos, pasos con checkpoints verificables (sabes si vas bien antes de avanzar), un ejercicio práctico al final, una tabla de troubleshooting con los errores más típicos, y unos recursos para profundizar opcionales.

### Convenciones tipográficas

| Elemento | Significado |
|----|----|
| código en línea | Nombres de archivos, comandos, variables o funciones |
| Bloque gris con monospace | Comando para ejecutar en terminal o código Python |
| 💡 Tip azul | Atajo, recomendación o paralelo SAS/R |
| ⚠️ Atención amarillo | Error común o algo que debes leer con cuidado |
| ✅ Checkpoint verde | Estado esperado: si lo ves, vas bien |

### Cómo trabajar con la guía

Sigue los pasos en el orden propuesto. Cada vez que aparezca un checkpoint en verde, detente y verifica que tu pantalla coincide con lo descrito antes de seguir. Si algo no funciona, consulta primero el Troubleshooting al final del módulo — el 80% de los problemas están ahí. Y cuando uses una IA para resolver dudas, primero entiende lo que te responde, después aceptas. Es la única forma de que el atajo no se convierta en lastre.
