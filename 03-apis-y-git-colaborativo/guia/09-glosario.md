# Glosario

| Término | Definición |
|----|----|
| API | Interfaz que expone funcionalidad de un programa para que otros programas la usen mediante un contrato definido |
| ASGI / uvicorn | Estándar y servidor que ejecutan aplicaciones web asíncronas de Python, como FastAPI |
| CI (integración continua) | Práctica de probar automáticamente cada cambio en una máquina limpia al integrarlo |
| Código de estado HTTP | Número de tres cifras que resume el resultado de una petición: 2xx éxito, 4xx error del cliente, 5xx error del servidor |
| Conflicto | Situación en la que dos cambios modifican las mismas líneas y Git necesita que una persona decida |
| Contrato | Especificación explícita de la entrada y salida de un componente; aquí, esquemas Pydantic más reglas de validación |
| Endpoint / ruta | Dirección concreta dentro de una API (`/procesar`) que responde a un método HTTP |
| Fixture | Dato de prueba fijo y conocido que permite probar un componente aislado |
| JSON | Formato de texto para intercambiar datos estructurados; el idioma común de las APIs |
| Merge | Integrar una rama en otra creando un commit de unión |
| Posestratificación | Ajuste de factores de expansión para que sumen totales poblacionales conocidos por grupo |
| Pull Request | Solicitud de integrar una rama a otra, con espacio para revisión, comentarios y pruebas |
| Pydantic | Librería de Python para definir modelos de datos tipados y validarlos |
| Rama (branch) | Línea de desarrollo paralela dentro de un repositorio; técnicamente, un puntero a un commit |
| Rebase | Reescribir una rama para que sus commits partan de otro punto, típicamente el `main` actual |
| Tamaño de muestra efectivo | Número equivalente de observaciones no ponderadas que darían la misma precisión; disminuye cuando los pesos son desiguales |
